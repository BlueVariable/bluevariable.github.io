# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

GitHub Pages site for Blue Variable Studio, served at `bluevariablestudio.com` (CNAME) from the `main` branch. It is a Jekyll site built by GitHub Pages itself: no local build step is required to deploy, and there are no runtime dependencies (no CDNs, no frameworks, no JS libraries). The design source is the Canva file "Blue Variable" (pages 1–9, 1366×768 artboards); local exports of it live in the git-ignored `_design/` folder.

The source files carry no comments on purpose: names are meant to explain themselves and this file holds the reasoning. When something needs explaining, add it here rather than as a comment.

## Structure

- `_config.yml` — site title, description, `author`, all external links (`links.*`, `wishlist_url`, `presskit_url`), `social_image` (the share image), the `plugins` list (`jekyll-feed` builds `/feed.xml` and `jekyll-sitemap` builds `/sitemap.xml`; both ship with the `github-pages` gem, so nothing is installed, but `jekyll serve` has to be restarted after a config change), post permalinks and defaults.
- `_layouts/default.html` — page shell (head, page-transition band, splash, icon sprite, header, main, footer, video modal, script). `_layouts/post.html` — devlog post page.
- `_includes/` — `head.html` (the meta description is the page's own, else the post excerpt, else the site description; the share image is `page.image` or `site.social_image`; it links the favicon trio and the feed, preloads Darumadrop, Londrina 900 and Urbanist 800 on every page and Glacial Indifference only on About and Contact, the two pages that set it, and its inline script decides whether the splash runs and, if so, injects a `preload` for the reveal SVG so the fetch in `site.js` hits the cache), `header.html` (the sticky `.site-header` holds only the ink bar with its masked torn bottom; the logo, nav, tagline and menu toggle live in the fixed `.site-header__layer` that follows it, plus the mobile menu; nav links carry `data-nav`; the `.site-nav__dot` span is the boiling dot that ends the active link like a full stop, "HOME."), `footer.html` (newsletter placeholder + socials), `socials.html`, `splash.html` (its `data-src` points at the reveal SVG, the same path the head script preloads), `wishlist.html` (the brush-stroke Steam button; params `href` and optional `class`), `video-modal.html` (the `<dialog>` for YouTube embeds, rendered once per page), `icons.html` (SVG sprite: steam, discord, itch, x, instagram, youtube, reddit, arrow, play, rss).
- Pages: `index.html` (home, `nav: home`, `splash: true`; the key art wrapper carries `data-tilt`; `.hero__news` under the button is the newest post's title and date, linking to the post; the page is exactly one viewport tall and never scrolls: `body.page-home` is a fixed `100dvh`, and `.site-main`, `.hero`, its `.wrap` and `.hero__art` all shrink (`flex: 1 1`/`0 1` with `min-height: 0`) so the key art gives up height instead of pushing the footer past the fold. The art keeps its aspect ratio while shrinking because the image itself is the flex item, sized `width: auto; height: auto` under `max-width`/`max-height: 100%`, rather than the wrapper cropping it), `games.html` (ends with `#presskit-purrfect-fit`, the game's own press kit: the key art in a framed tile with a download button, the facts list reusing `.facts` from the studio kit, the game description, and a link to the studio kit on Contact; it states nothing beyond "coming soon" and the note under it says screenshots and a trailer are not here yet), `news.html` (the timeline ends with a `.timeline__end` node holding an RSS `.btn`), `about.html` (inlines `_includes/mark-float.svg`, the blu.e mark whose letter groups `.f-b/.f-l/.f-u/.f-e/.f-dot` float idly and react to hover; each group carries `data-hoverable` and a transparent `.fl__hit` rect padded symmetrically around the glyph, because hover on bare letterforms only fires over the ink (about a sixth of the mark) and the symmetric padding leaves `transform-box: fill-box` centred so the float pivot does not move; the groups deliberately carry no `will-change: transform`, since with an infinite animation it promotes each letter to its own composited layer and composited hit-testing misses under a fractional display scale, such as a 1080p monitor at 125%, while behaving at a clean 2x. Hover is not read off the animated groups at all: a static `.mark__hits` layer of transparent rects sits last in the SVG, never animates, and drives each letter through `.mark:has(.hit-u:hover) .f-u`, so hit-testing never has to track a moving or composited layer. The in-group `.fl__hit` rects stay as the fallback for browsers without `:has()`, which is what the `@supports selector(:has(*))` guard on `.mark__hit` pointer-events switches between), `contact.html` (press kit lives under `#presskit`; the reasons list draws its dashes with a string `list-style`, so they are bullets rather than text; `.logos` is a two-column grid of equal cream tiles with a white border). Each sets `nav:` for the active link and `permalink:`. The post layout's "all news" link points at `/news/#<slug>`, so the router lands on the entry the reader came from (entries carry the post slug as `id`), and the page ends with older/newer links built from `page.previous`/`page.next`.
- `_posts/` — devlogs rendered on the News timeline (newest first, expandable with "see more"). Front matter: `title`, `date`, `game`, optional `steam` (wishlist URL, shows the button), `image` + `image_alt` + `caption` ("line one|line two") for the media card, `video` (YouTube URL, enables the play button/modal), `tags`. The first paragraph is the excerpt. `future: true` is set so scheduled dates still render.
- `404.html` — branded not-found page (`sitemap: false`). `robots.txt` points crawlers at the sitemap. `favicon.ico` (48 px) and `apple-touch-icon.png` (180 px) are `favicon.svg` rasterised, most easily with `chrome --headless=new --screenshot`; regenerate them when the favicon changes.
- `_tools/tears.js` + `_tools/tuner.html` — generator and visual tuner for the torn-edge masks (see Conventions). `_tools/social.py` renders the share image (needs Pillow). Underscore-prefixed, so Jekyll does not publish them.
- `PRODUCT.md` and `DESIGN.md` — the product record and the design record read by the Impeccable design skill (`/impeccable`): PRODUCT.md says who the site is for, what is real and what is placeholder and what the site may claim; DESIGN.md records the visual system as built (tokens in its YAML front matter, rules in prose) and is regenerated with `/impeccable document`, not edited alongside `site.css`. Both are excluded from the build in `_config.yml`, like this file. `.impeccable/` holds the local config of that skill and is git-ignored with the rest of the agent tooling.
- `assets/css/site.css` — all handwritten styles, in this order: fonts, tokens, reset, torn edges, cursor, header, mobile menu, buttons, decorations, footer, splash, page transition, then one block per page (home, about/team, games, news/post, contact/press kit, 404) and the mobile block at the end. `assets/css/tears.css` — generated, never edited by hand.
- `assets/js/site.js` — all behaviour, one `init*` function per feature: the nav dot (`initNavDot`), compact header, tagline ticker (rotates every `TICKER_MS` and also flips on click, which restarts the timer; the dot grows over it like a link), mobile menu, section labels (`initSectionLabels`), newsletter placeholder, devlog expand, video modal, mailto contact form, blue-band page transition (`initRouter`), the dot cursor/trail/splat (`initDot`), the key-art tilt (`initTilt`), the tuner bridge, first-visit splash. Content behaviour (expand buttons, play buttons, contact form, tilt) is bound once on `document` by delegation, so nothing needs re-initialising after a page swap; the section-label observer is the exception and is rebuilt by the router after each swap.
- Internal links do not reload the document: `initRouter` fetches the next page, swaps `<main>`, title, description, body class and the active nav link under the blue band, then drops the band (history/back-forward handled via `pushState`/`popstate`, with shorter `is-quick` durations). Scrolling under the band is instant (the page has smooth `scroll-behavior`, which would otherwise still be animating when the band drops), the band waits only for images inside the viewport (lazy images further down never load under the band), and a boiling dot appears in the band (`is-waiting`) if the fetch outlasts the cover. Clicking the link of the page you are on scrolls to the top instead of replaying the transition. The active link is set twice: from the URL on press (so it turns blue immediately and the nav dot hops) and from the fetched page's `page-<nav>` body class after the swap (which also covers post pages, whose URL is not a nav item).
- Arrival: when the band drops, `<main>` gets `is-arriving` for a moment and the children of every `.wrap` rise and fade in with an `nth-child` stagger (`arrive` keyframes), starting late enough that they are still moving as the band uncovers them. Sections marked `data-reveal` (Team, Press kit) are left out of that and instead play the same stagger every time they scroll into view: `initReveal` toggles `is-revealed` from an IntersectionObserver (rebuilt after each swap) whose bottom margin is -15%, so the stagger replays whenever the section is reached again and resets once the section's top drops back past 85% of the viewport, which is below anything already read; while the class is off their `.wrap` children sit at opacity 0; on Team the stagger runs over the `.member` cards rather than the grid. On hover-capable devices a member's bio and favourites are hidden until the card is hovered (they keep their space so the row never jumps); touch devices always show them. Without IntersectionObserver or under reduced motion they are revealed at once. The splash does not use the band (a hand-off to the band was tried and dropped): the blue pop fills the screen, then the whole splash fades out over the home page. Any click or key during the splash jumps straight to the pop.
- `assets/fonts/` — self-hosted fonts, all woff2: Darumadrop One, Londrina Solid 300/400/900, Urbanist 800, Glacial Indifference Regular/Bold (OFL). Only the weights the CSS actually asks for ship; Urbanist 700 and 900 were declared but never used and are gone. Glacial Indifference arrived as OTF and is now a lossless woff2 conversion (86 KB to 36 KB), not a subset: "Glacial Indifference" is an OFL Reserved Font Name, so a subset would have to be renamed, and the full face also keeps the Turkish characters the site sets in it. The face has no ğ/ş/Ğ/İ/Ş and Londrina Solid ships no latin-ext at all, so a heading or a reasons-list line containing those letters would fall back mid-word.
- `assets/img/brand/` — `logo.svg` (header wordmark), `logo-compact.svg` (compact header), `logo-reveal.svg` (animated intro for the splash), `favicon.svg`, `social.jpg` (the 1200×630 share image: the key art on the textured paper, output of `python _tools/social.py`). The About mark is not here: it is `_includes/mark-float.svg`, inlined so its letters can take `:hover`.
- `assets/img/presskit/` — the PNG logos shown on the press kit: `wordmark-white/black.png`, `mark-white/black.png`.
- `assets/img/team/` — team illustrations (`defne.svg`, `gokay.svg`, `nova.svg`).
- `assets/img/decor/` — recolourable mask art (`arrows.svg`, `brush.svg`, `bubble.svg`) and the `paper.webp` texture.
- `assets/img/purrfect-fit/` — game artwork: `keyart.webp` (home, Games, default OG image), `trailer.webp` (news media card). Any images dropped into `assets/img/purrfect-fit/screenshots/` appear automatically in the Games page grid.

## Conventions

- The cursor is the logo dot: on fine pointers `site.js` hides the native cursor (`html.has-cursor`) and moves a `.cursor` element whose `::before` is masked with the wobbling `--tear-dot` frames (the dot path is traced from `logo-reveal.svg` and lives in the generator). The wrapper only translates and scales (so the grow over links eases via the `scale` property without lagging the movement) while the `::before` carries the stepped boil. It grows over links and anything marked `data-hoverable` and then pulses while it stays there (`cursor-pulse` on the wrapper's `scale`, delayed by the grow so it takes over seamlessly), shrinks on press, hides over text fields and over iframes (the embedded player would otherwise leave it stuck at the frame's edge), turns paper-white over brand-blue backgrounds, sheds droplets while moving (`.trail`), and every press flings a ring of droplets (`.splat`, droplets only, no core dot). It does not sit on the pointer: a `requestAnimationFrame` loop eases it towards the pointer by `CURSOR.ease` of the remaining distance each frame, so it swings after the hand and settles into place, and the loop stops itself once it arrives (a CSS transition on `translate` would restart on every move and lag instead). The droplets are shed from that eased path rather than from the pointer, so they leave the dot the reader can see. Droplet counts/sizes/timings (design px) are the `DOT` object at the top of `site.js`; the follow speed is `CURSOR.ease` beside it and the cursor size is the `--cursor-size` token in `site.css`. The tuner's "Cursor & droplets" panel drives all of them live on the embedded site and prints the block to paste.
- Typography: every font size is a role token (`--t-note` 14, `--t-fine` 15.5, `--t-small` 17.2, `--t-label` 18.2, `--t-body` 19.5, `--t-lead` 21.5, `--t-nav-compact` 23, `--t-title-sm` 24.3, `--t-title` 28.6, `--t-title-lg` 34, `--t-poster` 38, `--t-title-xl` 40, `--t-display` 46.4, `--t-hero` 50.8, `--t-side` 67.8, `--t-code` 120, all in design px). They replaced 39 measured values that included pairs 0.3% apart doing different jobs; nothing moved more than about 5%, and a role that repeats now repeats exactly. The mobile block keeps its own hand-tuned sizes rather than inheriting the desktop roles, because the stacked phone layout wants different relative sizes, but writes them as `calc(N * var(--fpx))` so they scale the same way.
- Tokens sit on `--fpx`, not `--px`: `--fpx` is `--px` times `--text-zoom`, and `--text-zoom` is `clamp(1, tan(atan2(1rem, 16px)), 1.35)` behind an `@supports` guard. `tan(atan2())` is the way to get a unitless ratio out of two lengths in CSS; the guard leaves `--text-zoom` at 1 where the trig functions are missing, so those browsers behave exactly as before. A reader who sets a larger default font size gets type up to 1.35x larger while `--px` keeps the layout, the header and the one-viewport home page where they were; a smaller setting is ignored, since the design is already viewport-scaled.
- Leading is tuned per face, not per site. The hand and display faces have unusually short ink (Darumadrop's cap height is 0.59em, its uppercase ink 0.72em), so `--lh-cap` .81, `--lh-poster` .83, `--lh-hand-tight` .85, `--lh-hand` .9 and `--lh-flat` 1 are right for them. Urbanist and Glacial lowercase have a full 1.0em of ink, so the same ratios left about 2px of white between lines of a devlog; prose uses `--lh-prose` 1.5, `--lh-prose-narrow` 1.4 for short measures, `--lh-read` 1.45 for Glacial, `--lh-list` 1.3 for the reasons and facts lists, `--lh-head` 1.2 for headings and `--lh-ui` 1.12 as the body default the chrome inherits. Prose sets its own leading; never let a reading surface inherit a poster ratio.
- Measure: `.post__content` runs 600 design px (about 63 characters) and the News excerpt 540 (65). The excerpt used to be capped at 262, about 32 characters, with the right half of a text-only entry empty; the media entries' text column went from 300 to 500 so the widening is not swallowed by the grid, and `.entry__title` from 300 to 480 so a heading is no longer set narrower than the body beneath it.
- Every rule that sets `--font-hand` also sets `font-weight: 400`. Darumadrop One ships one weight, and 20 rules used to inherit `font-weight: 800` from `body`, so the browser synthesised a faux bold: the side labels, entry dates, captions, tags, fields and the mobile menu rendered heavier than the nav links, which set 400 explicitly. `.facts` likewise inherited 800 into Glacial, which has only 400 and 700.
- Each family has a metric-matched fallback face (`local("Comic Sans MS")` for Darumadrop, `local("Impact")` for Londrina, `local("Segoe UI")` for Urbanist and Glacial) whose `size-adjust` matches average advance width and whose ascent/descent overrides match the real face, so `font-display: swap` swaps without moving the page. Where the local font is absent the face simply does not resolve and the stack falls through as before. Recompute the percentages with fontTools if a family ever changes: `size-adjust` is the target's average advance over the fallback's, and each override is the target's metric divided by that.
- Motion tokens: `--dur-quick` (.15s, presses and the cursor), `--dur-base` (.3s, hovers, header, menu, dialog), `--dur-slow` (.45s, arrival, the nav dot's hop, expand) and `--dur-band` (.35s, the page-transition band each way; `--dur-band-quick`, .25s, for back/forward); the `COVER_MS`/`LEAVE_MS`/`QUICK_MS` constants in `site.js` sit 30ms above the band tokens so the swap never lands mid-transition; easings are `--ease-pop` (overshoot) and `--ease-out` (the band). The boil framerate (`.45s steps(1)`), the droplet animations (tuned in the tuner) and the splash pop keep their own literals. Every `:hover` rule sits inside `@media (any-hover: hover)` so nothing sticks after a tap on a phone (any-hover rather than hover so touch laptops with a trackpad keep their hovers); `:active` rules stay outside so presses read on touch too. `.btn` is the one button style: white on blue, turning blue on ink on hover; the brush-stroke button (`.brush-btn`, wishlist and Discord alike) is ink on a yellow stroke, turning yellow on an ink stroke on hover (the icon fills with `currentColor` so it follows the label).
- Layering: the cursor and its droplets sit at `z-index` 119–120, the footer's `.site-footer__wrap` at 121, the mobile menu at 122 (so it covers the lifted footer content) and the header content layer at 123 (so the logo and the menu toggle stay above the open menu). The dot therefore passes *behind* nav text and social icons rather than covering them, while the header bar (40) and footer background stay below it. That is why the header is split into a sticky bar and a fixed content layer, and why the footer has no `z-index` of its own. The two elevated layers are hidden while the splash is up (`.splash:not(.is-done) ~ …`) and the footer content while the band is up (`html.is-navigating`, set by the router for the length of a transition), otherwise they would float above the blue.
- The nav dot (`.site-nav__dot`) is positioned by `initNavDot` from the active link's box (`--x` just past its right edge, `--y` on the baseline, `--size` .3em) and hops with a `translate` transition; while the header changes height it is re-placed every frame with transitions off (`is-tracking`) so it rides the shrinking link instead of lagging behind it. The compact header keeps the tagline and shrinks it with `scale`, never with a smaller font: a font-size transition on the overshooting `--ease-pop` grew the text past its final size for a frame and rewrapped it to three lines. The hand-drawn decor (`.arrows`, `.bubble`, the brush stroke behind `.brush-btn`) boils with `decor-boil`, which drives the individual `rotate`/`scale` properties so it composes with each element's placement `transform`; `--boil` scales the amplitude (the brush uses .4). The About mark's letters react to hover the same way (`scale`/`rotate` on the `.fl` groups) on top of their float, which animates `transform`. The mobile menu and the video dialog animate in and out with `@starting-style` plus `transition-behavior: allow-discrete`, which older browsers simply skip.
- Side labels on About and Contact reflect the section under the middle of the viewport (`is-current`, an IntersectionObserver with a thin `rootMargin` band). The key art on the home page tilts towards the pointer: `initTilt` eases `--tilt-x`/`--tilt-y` towards the pointer every frame (`TILT.ease` per frame, `TILT.degrees` range) instead of using a CSS transition, which restarted on every move and felt laggy.
- Brand colors: ink `#1e1d1d`, paper `#f7f3ed`, cream text `#f5f3ef`, blue `#558eff`, yellow `#f5cb49`. Page backgrounds use `.paper` (cream + multiplied texture) so artwork blends.
- Desktop layout scales like the artboard: sizes are written as `calc(N * var(--px))` where N is the pixel value measured on the 1366-wide Canva page. Font sizes are the exception and go through `--fpx` instead (see Typography below), so the reader's own font-size setting moves the type without moving the layout. `--px` is the 1366×768 artboard fitted to the viewport (width or height, whichever binds, no upper cap: a 4K screen gets the design at about 2.8×, floor 0.72px), so borders, the cursor and the droplets are in design px too. About, Team, Contact and Press kit are at least `--section-min-h` (80vh) tall with their content centred on phones as well as desktop, so tall screens scroll one section at a time. Below 900px `--px` is 1px and layouts stack (mobile rules live at the end of `site.css`); the footer socials wrap there and the `@handle` takes a line of its own, because the seven icons and the handle on one row are wider than a phone and used to push the whole document sideways, which panned the fixed header (and with it the menu button) out of view.
- Recolorable vector art (`assets/img/decor/`) is applied with CSS `mask-image` so it takes `background-color`; the SVG files use `currentColor`. The News timeline line, the About divider and the tagline brackets are generated the same way as the torn edges (`--tear-line`, `--tear-bl`, `--tear-br`, see below) and boil with them.
- Torn paper edges are generated, not images. `assets/css/tears.css` holds the 24 `--tear-*` frame variables (SVG data-URI masks: gradient + `feTurbulence` speckle, hard-thresholded; `b`/`t`/`l`/`r` edges, `line`, `bl`/`br` brackets and `dot`, three frames each with the same speckle and a different low-frequency displacement). It is the output of `node _tools/tears.js > assets/css/tears.css`, and the recipe is the `DEFAULTS` object in that script. To change the look, open `_tools/tuner.html` in a browser (presets, sliders, live boil preview), press Copy and save the block as `tears.css`, then mirror the printed recipe into `DEFAULTS` so the script and the file agree. While `jekyll serve` runs, the tuner also embeds the live site and pushes the frames into it as you drag (a localhost-only `message` listener, `initTunerBridge` in `site.js`; browsers resolve `var()` inside `@keyframes` only when the animation starts, so the bridge restarts the boil).
- Tear geometry lives in three `site.css` tokens: `--tear-band` (height of the mask band, 45 design px), `--tear-depth-b` (how much of the band shows on a torn bottom, 10) and `--tear-depth-t` (22 on a torn top); the mobile block only overrides the tokens (30/7/15). `.torn-bottom` sections (and the header bar and the Games wrapper, which share the rule) are masked with the solid area plus the `--tear-b` band (`mask-size: 100% <band>`, no repeat so there are no seams) and the next block is pulled up under them; `.torn-top` sections, the news bands and the page-transition band use `--tear-t` (the band sets `--tear-depth-t` to the bottom depth so its tear is as shallow as the header's); the Games panel adds `--tear-l`/`--tear-r`. A `steps(1)` animation on `:root` cycles `--tear-*` through the three frames for a subtle line boil; the reduced-motion rule stops it on frame 1.
- Keep the site dependency-free: no build tools, package managers, or external CDNs.

## Local preview

Ruby 3.3 + MSYS2 are installed on the dev machine (`C:\Ruby33-x64`). Run:

```
bundle install            # once
bundle exec jekyll serve  # http://127.0.0.1:4000
```

The `github-pages` gem pins the same Jekyll version GitHub uses.

## Deployment

Pushing to `main` publishes the site via GitHub Pages. There are no tests.
